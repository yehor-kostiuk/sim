# План реалізації першої версії (MVP v1.0) — Startup Simulator

## 1. Технологічний стек реалізації

- **Frontend:** React + TypeScript, CSS Modules / Tailwind CSS, HTML5 Canvas або SVG для 2D-візуалізації офісу, бібліотека графіків (Chart.js або Recharts) для сторінки `Company Analytics`.
- **Backend:** Node.js + Express (або FastAPI) із REST API для обробки ігрових дій, симуляції тижня та генерації випадкових подій.
- **Збереження даних:** реляційна БД (SQLite / PostgreSQL) для зберігання профілів користувачів, стану компаній, штату працівників та історії `WeeklySnapshot`.
- **Тестування:** Vitest / Jest для модульних тестів економічної моделі та перевірки критеріїв приймання `AC-01`–`AC-09`.

## 2. Етапи розробки (Roadmap ЛР №4)

### Етап 1. Каркас проєкту, автентифікація та створення компанії (FR-01, FR-02, NFR-02)

- Ініціалізація клієнтської та серверної частин репозиторію, налаштування схеми БД за `Class Diagram`.
- Реалізація реєстрації, входу гравця та автозбереження стану компанії.
- Реалізація екрана створення компанії (введення назви, старт у стадії `Garage` з балансом `$5 000`, 1-м тижнем і 3 діями).

### Етап 2. Ігрове ядро: дії тижня, симуляція тижня та події (FR-03 — FR-08)

- Реалізація 4 типів управлінських дій (найм 4 видів працівників, покращення продукту, реклама, виплата бонусу) з валідацією ліміту дій і балансу.
- Реалізація двигуна завершення тижня (`nextWeek`): нарахування доходу, списання зарплат, перерахунок `Satisfaction`, звільнення працівників із `satisfaction <= 0`.
- Наповнення бази з 12–15 випадкових подій (`GameEvent`) із 2–3 варіантами вибору для кожної події.
- Реалізація переходів за 5 стадіями (`Garage` → `Exit`) та екранів банкрутства (`Bankrupt`) і перемоги (`Completed`).

### Етап 3. 2D-візуалізація офісу та аналітика (FR-09, NFR-01, NFR-03)

- Створення 2D-сцени офісу з візуальним відображенням працівників та зміною вигляду приміщення відповідно до стадії компанії.
- Реалізація сторінки `Company Analytics` із 4 графіками (`Money`, `Reputation`, `Product Quality`, `Team Size`) на основі `WeeklySnapshot`.

### Етап 4. Верифікація та підготовка до релізу

- Прогін автотестів за матрицею `traceability.md` (`TC-01`–`TC-12`).
- Перевірка швидкодії перерахунку тижня (`NFR-01 <= 1 с`) та юзабіліті-тест першого тижня (`NFR-03 <= 2 хв`).
