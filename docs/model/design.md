# Проєктна документація та моделі системи — Startup Simulator v1.0

## 1. Загальна архітектура рішення

Вебзастосунок **Startup Simulator v1.0** побудовано за клієнт-серверною архітектурою з чітким відокремленням ігрової економічної моделі від візуального інтерфейсу:

- **Клієнтська частина (Frontend):** односторінковий вебзастосунок (SPA), що відповідає за рендеринг 2D-сцени офісу відповідно до поточної стадії розвитку компанії, відображення панелі характеристик (`Money`, `Team`, `Product`, `Reputation`), модальних вікон подій та графіків аналітики.
- **Серверна частина та ігрове ядро (Backend / Domain Engine):** реалізує бізнес-логіку покрокового тижневого циклу, перевірку ліміту дій (до 3 на тиждень), розрахунок доходів, зарплат і задоволеності працівників, генерацію випадкових подій (набір із 10–20 сценаріїв) та перевірку умов перемоги або банкрутства.
- **Рівень збереження даних (Persistence):** забезпечує автентифікацію гравця та автоматичне збереження стану компанії, складу команди й тижневих знімків між сесіями.

## 3. Модель предметної області (Class Diagram)

Діаграма класів фіксує структуру даних гри без прив’язки до конкретних фреймворків:

![Class Diagram](images/class-diagram.svg)

### Призначення ключових сутностей

- **`User`** (`id`, `username`, `email`) — обліковий запис гравця, який може володіти однією або кількома збереженими компаніями (`login()`, `startNewGame()`).
- **`Company`** (`id`, `name`, `balance = 5000`, `reputation`, `productQuality`, `currentWeek = 1`, `actionsRemaining = 3`, `state`) — центральна сутність стартапу, що керує балансом, наймом персоналу та переходом між тижнями (`nextWeek()`, `hireEmployee()`, `updateBalance()`).
- **`CompanyState`** (`«enumeration»`) — перелік можливих станів ігрової сесії: `Active`, `Bankrupt`, `Completed`.
- **`Employee`** (`id`, `name`, `role`, `salary`, `productivity`, `satisfaction`) — працівник одного з 4 типів посад; впливає на продуктивність і витрати компанії, а при падінні `satisfaction <= 0` звільняється (`calculateOutput()`, `updateSatisfaction()`).
- **`WeeklySnapshot`** (`id`, `weekNumber`, `revenue`, `expenses`, `endingBalance`, `reputation`, `productQuality`, `teamSize`) — агрегований знімок показників наприкінці кожного тижня для побудови графіків аналітики; реалізує інтерфейс `IReportable` (`generateReport()`).
- **`GameEvent`** (`id`, `title`, `description`, `financialImpact`, `reputationImpact`, `productImpact`, `weekNumber`) — випадкова подія тижня, що змінює параметри компанії залежно від рішення гравця (`applyEffect()`).

## 4. Модель життєвого циклу компанії (State Machine Diagram)

Діаграма станів описує допустимі переходи головного об’єкта `Company` протягом ігрової сесії:

![Company State Machine](images/company-state-machine.svg)

1. **`Active`:** початковий стан після створення компанії (`Garage`, `$5 000`, тиждень 1). Поки після завершення тижня виконується умова `баланс > 0 && не фінал`, компанія залишається в стані `Active` і поступово проходить стадії розвитку (`Garage` → `Small Startup` → `Growing Company` → `Corporation`).
2. **`Bankrupt`:** термінальний стан поразки, у який компанія переходить при завершенні тижня з умовою `баланс <= 0`. Усі подальші ігрові дії блокуються.
3. **`Completed`:** термінальний стан перемоги, у який компанія переходить після досягнення умов фінальної стадії `Stage 5: Exit`.
