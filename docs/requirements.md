# Специфікація вимог (SRS) — Startup Simulator v1.0

## 1. Межі першої версії (Scope v1.0)

### Входить до v1.0 (In Scope)

- Реєстрація, авторизація гравця та автоматичне збереження прогресу компанії між сесіями.
- Створення нової компанії (введення назви для єдиного базового типу стартапу) зі стартовими показниками стадії `Garage`.
- Покроковий ігровий цикл (1 хід = 1 тиждень) із лімітом до 3 управлінських дій на тиждень (набір із 5–10 базових типів дій: найм 4 типів працівників, покращення продукту, запуск реклами, виплата бонусу тощо).
- Динамічний перерахунок 4 основних характеристик компанії: гроші (`Money`), команда (`Team`), якість продукту (`Product`), репутація (`Reputation`).
- Управління працівниками з параметрами навички (`Skill`), задоволеності (`Satisfaction`) та зарплати (`Salary`), включно з автоматичним звільненням при падінні задоволеності до 0.
- База з 10–20 щотижневих випадкових подій із 2–3 варіантами відповіді та наслідками для параметрів компанії.
- Лінійний розвиток компанії за 5 стадіями (`Garage` → `Small Startup` → `Growing Company` → `Corporation` → `Exit`) та умови завершення гри (банкрутство при `Money <= 0` або перемога при досягненні фінальної стадії).
- 2D-візуалізація стану одного офісу та сторінка тижневої аналітики (`Company Analytics`) із графіками зміни 4 показників.

### Не входить до v1.0 (Out of Scope)

- Вибір специфіки бізнесу (GameDev, E-commerce, FoodTech) з унікальними подіями для кожного типу.
- Кастомізація інтер'єру офісу та система досягнень (achievements).
- Суттєве розширення бази випадкових подій і кризових ситуацій понад обсяг v1.0.
- Багатокористувацький режим (multiplayer) та симуляція реального фондового ринку акцій.
- Автономний штучний інтелект працівників і складний пошук шляху (pathfinding) на карті.
- Мобільна та десктопна версії застосунку.

## 2. Функціональні вимоги (FR)

| ID        | Вимога                                                                                                                                                                                                               | Критерій приймання (AC)                                                                                                                                                   |
| :-------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **FR-01** | Система повинна дозволяти користувачу зареєструватися, увійти в обліковий запис та завантажити збережений прогрес своєї компанії.                                                                                    | **AC-01:** Після повторного входу гравець бачить актуальний тиждень, баланс, склад працівників та історію компанії без втрати прогресу.                                   |
| **FR-02** | Система повинна дозволяти гравцю створити нову компанію, задавши її назву, зі стартовими показниками стадії `Garage`.                                                                                                | **AC-02:** Створена компанія відкривається на 1-му тижні з початковим капіталом $5 000, лімітом у 3 дії та 2D-сценою офісу стадії `Garage`.                               |
| **FR-03** | Система повинна дозволяти гравцю виконати до 3 управлінських дій протягом поточного тижня (найм працівника одного з 4 типів, покращення продукту, запуск реклами, виплата бонусу).                                   | **AC-03:** Кожна виконана дія зменшує лічильник доступних дій на 1, списує вартість дії з балансу `Money` та змінює відповідні показники компанії чи працівника.          |
| **FR-04** | Система повинна блокувати виконання управлінської дії, якщо ліміт дій на поточний тиждень вичерпано або балансу `Money` недостатньо для її оплати.                                                                   | **AC-04:** При нестачі грошей або дій операція відхиляється, баланс не змінюється, а гравець отримує повідомлення про причину обмеження.                                  |
| **FR-05** | Система повинна при завершенні тижня обчислювати дохід (на основі якості продукту та репутації), списувати зарплати всіх активних працівників, оновлювати їхню задоволеність і зберігати тижневий знімок показників. | **AC-05:** Номер тижня зростає на 1, ліміт дій відновлюється до 3, баланс змінюється на різницю доходів і зарплат, а новий запис додається в історію компанії.            |
| **FR-06** | Система повинна автоматично звільняти працівника при завершенні тижня, якщо його рівень задоволеності (`Satisfaction`) зменшився до 0 або нижче.                                                                     | **AC-06:** Працівник із `Satisfaction <= 0` видаляється зі складу команди, його зарплата не враховується в наступних тижнях, а гравець отримує сповіщення про звільнення. |
| **FR-07** | Система повинна генерувати щотижневу випадкову подію (із набору 10–20 сценаріїв) та змінювати параметри компанії чи працівників відповідно до обраного гравцем варіанта рішення.                                     | **AC-07:** Після вибору одного з варіантів події параметри `Money`, `Reputation`, `Product` або `Satisfaction` змінюються на значення, задані умовами події.              |
| **FR-08** | Система повинна оновлювати стадію розвитку компанії залежно від чисельності команди, завершувати гру поразкою при `Money <= 0` та завершувати гру перемогою при досягненні фінальної стадії `Exit`.                  | **AC-08:** При `Money <= 0` фіксується банкрутство і подальші ходи блокуються; при досягненні умов стадії `Exit` фіксується перемога гравця.                              |
| **FR-09** | Система повинна надавати гравцю перегляд графіків історичної зміни 4 показників (`Money`, `Reputation`, `Product Quality`, `Team Size`) за всі пройдені тижні.                                                       | **AC-09:** На сторінці `Company Analytics` кожна точка на графіках відповідає збереженим тижневим підсумкам компанії.                                                     |

## 3. Нефункціональні вимоги (NFR)

| ID         | Категорія              | Вимога та спосіб перевірки                                                                                                                                               |
| :--------- | :--------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **NFR-01** | Продуктивність         | Перерахунок економічної моделі при завершенні тижня та оновлення 2D-офісу повинні займати **не більше 1 с** у 95% переходів у браузері (перевірка заміром часу відгуку). |
| **NFR-02** | Надійність збереження  | Прогрес компанії автоматично зберігається після кожного завершеного тижня; при перезавантаженні сторінки втрата становить **0 завершених тижнів**.                       |
| **NFR-03** | Зручність використання | Новий гравець без зовнішньої інструкції повинен створити компанію та завершити перший ігровий тиждень **не більше ніж за 2 хвилини** (перевірка користувацьким тестом).  |
